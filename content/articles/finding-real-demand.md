# 怎样找到并筛选值得做的需求

从具体任务寻找机会，用已有证据和自身条件做取舍。

:::takeaways 先看结论

- **真实痛点也要取舍**：频率、后果、替代方案都影响价值。
- **比较具体任务**，别把宽泛产品想法直接打分。
- **先查关键短板**，写清选择理由和推翻选择的条件。

读完完成：**需求取舍表**，选一个当前值得继续验证的方向。

:::

![小黑从散落的需求便签中挑出一张，折成能承重的小凳](/assets/finding-real-demand-illustrations/01-choose.png)
*想法很多，本轮先选一件能落地的事。*

## 01 · 从任务现场找线索

| 从哪里找 | 继续追问 |
|---|---|
| 自己的工作 | 别人有同样任务，还是只有我遇到？ |
| 客户反馈、社群讨论 | 为什么要这个功能，实际卡在哪里？ |
| 行业经验 | 哪些字段、确认环节和资料限制不能省？ |

**把功能愿望往前问一步。** “需要批量处理”可能是量变大、交期缩短，也可能是重复填资料；解法不一定相同。

:::details 进一步理解 · 真实痛点为什么还不够

遇到一个真实痛点，不表示它应该成为你的下一个产品。有人确实觉得麻烦，但发生得很少；有人每天都在做，却已有足够便宜的替代方案；还有一些问题很重要，但你暂时无法接触购买者。需求判断需要同时看问题本身、解决条件和你的能力。

这一章承接前一章收集的事实，帮助你从几个候选任务中选出一个值得继续验证的方向。最终成果不是一张高分榜，而是一份能解释为什么现在选它、暂时放下其他方向的取舍记录。

自用需求是一个好入口，因为你知道过程中的细节。但你也可能拥有普通用户没有的技能、资料或耐心。把自己怎么完成任务写下来，再找处于相近场景的人核对：他们是否也有这个任务？遇到的阻碍是否相同？

客户反馈和社群讨论提供另外两类线索。收到“希望加批量处理”的建议时，先问为什么需要批量：任务量变大、交付时间变短，还是目前每次都要重复填资料？同一个功能愿望背后可能是完全不同的问题，对应的解决办法也不同。

行业经验的价值，常在于知道什么不能省略。例如一个结果必须经过谁确认、什么字段不能错、哪种资料无法直接共享。这些限制会帮助你判断方案是否可用，但仍需与当前使用者核对，避免把过去的流程当作今天的全部事实。

:::

## 02 · 把候选需求写成同一种格式

**谁 → 在什么情况下 → 要完成什么任务 → 现在怎样做 → 哪里不满意。** 先写结果，保留不同解法。

| 过早规定功能 | 改写为可观察的结果 |
|---|---|
| 做一个海报生成器 | 活动开始前，交付价格正确的门店物料 |
| 自动生成整套营销方案 | 先拆出一个具体任务，再与其他需求比较 |

每条需求旁边标注 **已观察／当事人自述／待验证**。表达愿望、经历问题和已经购买解决方案，支持的判断不同。

:::details 进一步理解 · 为什么先写结果再写功能

每条候选需求都用相同粒度记录：谁，在什么情况下，要完成什么任务，现在怎样做，为什么不满意。不要把“自动生成整套营销方案”和“把表格中的价格填进海报”直接放在一张榜上比较；前者尚未拆成能观察的任务。

先描述结果，不急着写功能。“让运营在活动开始前交付价格正确的门店物料”允许多种解法；“做一个海报生成器”过早规定了产品形态。保留这种开放性，你才有机会发现流程调整、模板或现成工具已经足够。

将证据放在描述旁边。有人亲自经历过、有人表达愿望、有人已经购买解决方案，三者支持的判断不同。可以用“已观察”“当事人自述”“待验证”标记，不需要制造一个看起来精确的可信度分数。

:::

## 03 · 对照五个条件，先补最薄弱的一项

![小黑扶着缺少一个轮子的需求小车，寻找缺失的条件](/assets/finding-real-demand-illustrations/02-missing-condition.png)
*关键条件缺失时，其他优势不能简单相加补救。*

| 比较条件 | 要找的证据 | 证据不足时的动作 |
|---|---|---|
| 发生频率与后果 | 最近几次任务和失败影响 | 还原实际工作记录 |
| 替代方案 | 当前工具、费用、人工处理 | 走一遍现有流程 |
| 改变成本 | 资料迁移、学习、协作要求 | 做一次最小试用 |
| 触达条件 | 能接触的使用者与购买者 | 验证一个真实入口 |
| 交付优势 | 经验、材料、验收能力 | 完成一份结果样例 |

**不要机械加总。** 拿不到必要资料，可能就无法交付；“会用 AI”要落到更容易完成的具体环节。

:::details 进一步理解 · 频率、后果与改变成本

首先看发生频率与不解决的后果。频率低不等于不值得做，关键是后果；频率高也不自动意味着高价值，可能每次只需要极小的努力。把两者一起看，才不会只挑那些抱怨声音最大的任务。

然后看替代方案。对方已经在用表格、人工外包、现有软件，甚至决定暂时不做。你要比较的是整个改变成本，而非单次生成速度。迁移资料、训练同事、检查错误都可能抵消节约的时间。

最后看你能否接触使用者、能否交付结果。已有渠道、理解验收方式、拥有可合法使用的资料，都可能构成优势。“会用 AI”过于宽泛，应当落到你比别人更容易完成的具体环节。

| 比较条件 | 要找的证据 | 证据不足时的动作 |
|---|---|---|
| 发生频率与后果 | 最近几次任务和失败影响 | 还原实际工作记录 |
| 替代方案 | 当前工具、费用、人工处理 | 走一遍现有流程 |
| 改变成本 | 资料迁移、学习、协作要求 | 做一次最小试用 |
| 触达条件 | 能接触的使用者与购买者 | 验证一个真实入口 |
| 交付优势 | 经验、材料、验收能力 | 完成一份结果样例 |

不要把表格机械加总。有一项关键条件完全不成立，例如拿不到必要资料，其他项目再高也无法补救。先找最薄弱且影响最大的条件，决定是否值得为它设计验证。

:::

## 04 · 选择一个方向，同时写下退出条件

:::case 教学假设 · 两个方向怎么选

你熟悉内容制作：一边是替陌生行业预测市场规模，一边是替已有合作对象整理常用内容资料。

如果前者缺数据和验收能力，后者可能更适合本轮验证。**这是当前条件下的选择，不是普遍的价值排名。**

:::

:::steps 把决定写清楚

1. **选什么**：谁的哪项任务，依据是什么。
2. **暂缓什么**：缺少哪个条件，什么变化值得重看。
3. **验证什么**：当前最大未知，下一步具体动作。
4. **何时退出**：哪种发现会推翻选择。

:::

若使用者没有该任务，或可接受价格无法覆盖交付成本，就重新评估。本方法帮助小团队控制探索投入，不能替代完整市场研究。

:::details 进一步理解 · 让选择可以被新证据改变

选择当前最值得验证的一个方向，同时写明暂缓其他方向的原因。原因应该可被新证据改变，例如“目前接触不到购买者”，而不是“感觉没有前景”。这样以后条件变化时，你能重新判断，不必从头翻找。

教学假设：你熟悉内容制作，有两个方向——帮陌生行业预测市场规模，或帮已有合作对象整理重复使用的内容资料。前者可能更吸引人，但如果缺乏数据和验收能力，后者可能更适合作为本轮验证。这个选择源于当前条件，不代表后者在所有情况下都更有价值。

把退出条件写在开始之前：哪一种发现会推翻选择？若真实使用者几乎没有这个任务，或者可接受的价格无法覆盖交付成本，就应该重新评估。不要为了保护已经写好的代码，把需求描述越改越宽。

完成模板后，请用一段话解释选中的需求：它解决谁的什么任务；依据是什么；最大未知是什么；下一步怎样验证。解释中如果不断出现“应该”“大家都会”，就回到事实栏补材料。

这套判断适合帮助小团队控制探索投入，无法替代完整市场规模研究或商业可行性评估。选出方向后，第三章会把它缩成一段能完成、能检查的交付流程。

:::
