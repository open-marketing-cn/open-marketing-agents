# 开发前，怎样验证有人需要、有人愿意付费

先把谁来用、谁来买、怎样找到他写清楚，再决定要不要投入开发。

:::takeaways 先看结论

- **先找到具体任务**，再决定做什么功能。
- **问最近发生的事**，把经历与自己的推断分开。
- **观察真实行动**，提前写好继续、调整或暂停的依据。

读完完成：**一页验证计划**，知道找谁、验证什么、怎样判断。

:::

## 01 · 找对人，也找对场景

先补完这句话：当【某类人】遇到【具体任务】时，正在用【现有做法】完成，却在【某一步】付出额外代价。

| 要分清的人 | 要问清的事 |
|---|---|
| 使用者 | 谁做这项任务，哪一步最费力？ |
| 购买者 | 谁能批准预算，为什么愿意付费？ |
| 风险承担者 | 出错后谁负责，结果由谁确认？ |

**入口要能执行。** “发小红书”只是渠道；找到正在讨论门店物料修改的人，才是可以开始的接触动作。

:::details 进一步理解 · 为什么要拆开角色

开始做产品时，最容易先解决自己熟悉的问题：选模型、画界面、接支付。它们都有清晰的完成状态，却不能回答一个更早的问题：什么人会在什么情况下选择你的方案？如果这件事仍然模糊，功能越完整，改变方向的成本就越高。

前置营销从理解一次真实的选择开始。一个人正在完成某项任务，手上已经有一种做法；你的方案要让他愿意改变。改变可能意味着学习、迁移资料、让同事配合，甚至承担出错责任。因此，“更快”“更智能”只有放进具体任务才有意义。

本章要完成的，是一份可以执行的验证计划。它不要求你先证明整个生意成立，而是找出目前最不确定、同时最影响下一步投入的判断，设计一个能减少这项不确定性的动作。

先用一句话描述场景：“当【某类人】遇到【具体任务】时，正在用【现有做法】完成，但会在【某个环节】付出额外代价。”把“需要做营销的小团队”收窄到“每周需要给多个门店交付活动海报、最后还要逐店改价的运营”，你才能知道应该询问谁、查看什么材料。

使用者与购买者可能是同一个人，也可能不是。运营觉得工具好用，并不表示负责人能批准采购；负责人认可效率，也不表示一线愿意改变工作方式。把两者分别写出，并补充：谁承担失败的后果？谁能提供试用材料？谁决定继续使用？早期不必找齐所有人，但要知道自己拿到的是哪一方的反馈。

触达入口也要具体。“发小红书”是渠道名称，“在讨论门店物料修改的内容下找到正在做这件事的人”才是可执行的入口。选一个你目前能够接触的场景开始，不把尚未建立的流量能力当作既有条件。

:::

## 02 · 还原最近一次，别让对方预测未来

1. 最近一次任务是怎么开始的？
2. 用了什么工具，在哪里停住或重做？
3. 不解决会怎样，已经付出了什么代价？
4. 能否一起查看脱敏后的实际材料？

**事实栏只写发生过的事。** “改了几个版本”是经历；“所以愿意订阅”是待验证的推断。

:::details 进一步理解 · 怎样避免诱导反馈

访谈的任务是还原已经发生的工作。请对方讲最近一次怎么做，从收到任务到交付，在哪里停住、找谁帮忙、有没有重做。能查看脱敏材料时，材料通常比一句“很麻烦”更容易暴露具体限制。

可以依次追问：任务由什么触发？原来用了哪些工具？最费力的一步是什么？如果不做会怎样？之前有没有为解决它付出时间或费用？避免先介绍一长串功能再询问“你会买吗”，因为对方很容易评价你的表达，而不是自己的需要。

记录时将观察和解释分开。“上次来回改了几个版本”是一段经历；“因此一定愿意订阅”是你的推断。只有前者可以直接进入事实栏。没有发生过的事，写成待验证假设。

:::

## 03 · 选一个能观察行动的验证

![小黑衡量轻飘的喜欢气泡、交来的材料和已付款包裹](/assets/before-building-illustrations/02-evidence.png)
*不同的行动，回答不同的问题。付款也不自动证明需求可持续。*

| 现在最不确定什么 | 本轮可以怎么做 | 能支持什么判断 |
|---|---|---|
| 任务是否真实 | 还原最近一次工作 | 场景与代价确实存在 |
| 方案是否有用 | 手工交付一个结果 | 对方能否实际使用 |
| 是否愿意购买 | 说明范围、价格后发出真实邀请 | 这次是否愿意为结果付费 |

:::steps 验证四步

1. **写假设**：谁愿意为哪种结果采取什么行动。
2. **备材料**：说明、结果样例、下一步入口。
3. **看行动**：记录接触人数和实际后续行为。
4. **做决定**：在约定时间继续、调整或暂停。

:::

**手工交付要如实说明。** 提前说清完成方式、时间、范围；收费时说明交付与退款条件。

:::details 进一步理解 · 行动能证明什么、不能证明什么

访谈后，选择成本最低、但能检验关键判断的方式。如果不知道任务是否值得解决，先继续还原工作；如果知道任务存在，却不知道方案有没有用，可以手工完成一次；如果结果有用，却不知道是否有购买意愿，就说明交付范围和价格，提出真实的试用或购买邀请。

1. 写出假设：哪类人愿意为哪种结果采取什么行动。
2. 准备最少材料：一段说明、一个结果样例、清晰的下一步入口。
3. 向匹配场景的人展示，记录接触人数以及后续行为。
4. 按事先约定的观察窗口回看，决定继续、调整或暂停。

这里的行动可以是愿意提供真实材料、预约一次实际使用、让团队参与测试，或者付款。它们分别支持不同判断。提供材料说明对方愿意投入一点成本，不等于购买成立；付款比口头喜欢更接近商业验证，但也可能来自熟人支持或一次性需要。

不要把手工交付伪装成已经自动化的产品。明确当前如何完成、需要多久、交付什么；如果测试涉及收费，也应提前说清交付和退款条件。

:::

## 04 · 先定判断依据，再看结果

:::case 教学假设 · 门店海报改价

运营愿意发来旧物料，支持“场景真实且愿意试”。结果进入下一次活动、对方仍愿意继续使用，才开始支持“方案能融入工作”。

**这是假设示例，不是真实成交案例。**

:::

- 没有这项任务 → 调整人群或问题。
- 有任务却不愿试 → 检查信任、改变成本和结果表达。
- 试过却不回来 → 先查任务有没有完成。

把时间、投入上限与改变判断的条件提前写进模板。**小样本先看具体行为和拒绝原因，不急着算精确转化率。** 不同业务的购买周期不同。

:::details 进一步理解 · 阈值、案例解释与适用范围

阈值应当来自你的投入约束，不能随结果临时变化。先写下最多花多少时间、接触什么样的人、观察什么行动，以及什么结果会让你改变判断。样本很少时，不急着算看似精确的转化率；先检查遇到的人是不是目标使用者、拒绝原因是否重复。

教学假设：你想帮助门店运营减少海报改价工作。第一次交流后，对方愿意把旧物料发给你，这支持“场景真实且愿意试”；但只有当结果进入下一次活动、对方仍愿意继续使用，才开始支持“方案能融入工作”。这是解释证据层次的假设，不是真实成交案例。

如果多数人没有这项任务，调整人群或问题。如果任务真实但没人愿意试，检查信任、迁移成本与结果表达。如果有人试却不再回来，先查是否完成任务，不要马上加大获客。只有在关键风险降低后，才增加开发投入。

下面的模板中，每一项都应能影响行动。“待确认”是有效答案，但要配上验证办法。填完后检查三件事：能不能找到对应的人？观察到的行为能不能回答假设？即使失败，是否知道下一步该改哪里？

本章只能帮助你降低早期判断风险。企业采购、低频高价值服务和个人订阅的决策周期不同，不能套用同一个验证时限。下一章会进一步处理多个真实需求之间的取舍。

:::
