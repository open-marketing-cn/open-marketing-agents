## 口播逐字稿

上次我说，我想给中国品牌做一个 all in one 的 AI 营销工作台。

那条视频爆了。

所以今天我来交一下作业：这个房子，我真的开始搭了。但里面还没有一件经过真人验证、可以直接让大家安装的“家具”。

我先给你们看一下现在长什么样。

我没想到上条视频会把这么多不同的人带出来：品牌、SEO、投放、电商、Agency、Consulting，还有 AI 产品的开发者和创始人。

隔行如隔山，但他们都在关注同一件事。后来我发现，大家其实不是因为同一个理由来的。

营销人想干活更快，给老板交差、服务客户都更顺；Agency 和 Consulting 想把很依赖个人经验的流程做得更稳定；独立开发者会做产品，但缺营销方法，也缺真实场景。

所以我觉得这件事确实有意义。但我也突然明白，为什么一直没有人把它做出来：它真的是脏活累活。

你们现在看到的，是我按照以前做品牌营销的流程搭出来的六个房间：从 Insights 一直到 Performance。简单讲，就是从找问题、找证据，一直到内容怎么做、怎么交付、最后怎么复盘。

我是个完全不懂技术的文科生，以前是设计背景。我先按照自己的理解，把房子的结构搭起来，把每个位置留出来。比如 Insights 里面，消费者语言、评论、公开内容怎么整理，我都已经留了位置。

但这个版本还在整理，不能直接给大家用。因为我不想最后做出来的，只是一个看起来很全的玩具。

现在真正卡住我的，是：什么样的 Agent 和 Skill，才有资格搬进来？

企业内部真正好用的 Agent，往往依赖内部 SOP、客户资料和合规要求，不一定能公开。市面上开源的 Agent 又特别多，同一个 SEO 可能有二三十个，有的真的好用，有的只是套了一个壳。

更麻烦的是，同一个结果，营销老手可能只打 6 分，刚开始做营销的开发者可能打 8 分、9 分。不同行业、不同岗位，对“好用”的判断也不一样。

所以我现在觉得，最前置的工作不是继续收集，而是先把测试和市场认证做出来。

第一轮，我们先做中国市场，跨境先放一放；也不急着把六个房间装满，先从 Insights 开始。再具体一点，先测试现在已经整理出来的“消费者语言洞察 Agent”。

我的想法是，找三个不同消费品品类的脱敏任务，让不同经验、不同岗位的营销人真实去用。技术检查是一层，但最后一定要有人判断：证据能不能查，结果能不能拿去工作，还要改多少，哪些地方不能让 AI 下结论。

这套评分方法跑通以后，我们再用同一套标准比较其他 Agent。通过了，才进入仓库，才标成可安装；没通过，失败原因也公开。

那大家怎么共创？我不太想只收一句“我愿意共创”。你可以真的搬一件家具进来：一个你用过的 Agent 或 Skill，加上你怎么用、需要什么资料、最后交付什么，再配一个脱敏案例。你也可以做真实试用、技术测试、文档或者维护。

回报这块我还没有完全定死。能确定的是，每一项真实贡献都会留下署名和记录；持续维护的人，可以进入核心维护组，参加项目会，也参与版本和验证标准的讨论。

至于贡献者能不能提前试用候选能力，特别好的 Skill 要不要保留收费或者商业合作的空间，这些还在讨论，我不想现在就说成已经定了。

接下来我会把每周做了什么、卡在哪里、哪些 Agent 被留下、哪些被淘汰，都在小红书和 GitHub 上公开。

围观当然没关系。但如果你愿意做第一轮真实试用，或者手里真的有一件自己用过的“家具”，可以直接告诉我：你能带来什么，你愿意测试什么。

我们真的开始搭了。

## 画面顺序

1. 开头直接放上一条视频的封面或数据截图；
2. 说“房子真的开始搭了”时，立刻切到工作台六个房间；
3. 说“没有一件可安装”时，展示候选状态与验证为空；
4. 说三个卡点时，右侧只保留三个词：企业不公开 / 开源质量不一 / 人的评分不同；
5. 说第一轮时，展示 `Insights → 消费者语言洞察 → 3 个品类真人测试`；
6. 结尾右侧展示 README 的“你可以怎么参与”，停在具体贡献方式上。
