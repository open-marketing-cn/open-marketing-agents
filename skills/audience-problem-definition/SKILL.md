# 受众与问题定义

把“所有可能会买的人”缩成首轮值得服务和验证的人群，把宽泛痛点改成有场景、有替代、有证据的问题陈述。

## 必要输入

- 产品或服务能做什么，以及当前业务限制。
- 至少一份用户访谈、评论、行为数据、销售记录或明确标记的团队假设。
- 用户正在使用的替代方案或“不处理”的方式。
- 当前要做的决策：首发人群、研究招募、产品范围或 Campaign 受众。

没有用户证据时，不制作“已验证画像”；只输出假设版并列出验证方法。

## 工作步骤

1. 把材料分为观察事实、用户原话、团队意图和未经验证假设。
2. 生成候选人群段：共同场景、触发、问题强度、现有替代、可触达性与业务适配。
3. 用证据强度、问题频率、紧迫性、可服务性和可触达性比较候选，不伪造分数精度。
4. 将优先人群写成“在【场景】下，当【触发】发生，他们需要【结果】，但被【阻力】挡住，目前用【替代】”。
5. 明确首轮不服务谁，以及这一取舍的原因。
6. 为每个关键假设设计最小验证问题或观察证据。

## 交付文件

在 `open-marketing-output/audience-problem-definition/` 或用户指定目录创建：

- `audience-priority.md`：候选人群、证据、取舍与优先顺序。
- `problem-statements.md`：场景化问题陈述与相关原话/记录。
- `assumption-log.md`：假设、证据状态、验证方法、负责人和下一次复审时间。

## 人工决定

业务负责人选择优先服务和暂时放弃的人群，确认问题是否值得解决，并决定哪些假设可以进入下一轮测试。

不得推断市场总体比例、真实付费意愿、购买必然性或公司未说明的战略优先级。
