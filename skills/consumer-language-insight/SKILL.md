# 消费者语言洞察

回答一个具体问题：消费者如何描述问题、场景、替代方案、顾虑和期待？所有判断必须能回到用户提供或明确授权访问的记录。

## 开始前

先确认：

1. 品牌或品类、目标市场、时间窗口。
2. 1–3 个研究问题。
3. 至少一组评论、访谈、客服记录或公开表达。
4. 数据是否包含链接、日期、平台、购买/使用阶段等可追溯字段。

缺少研究材料时停止，列出具体缺口。只有用户明确要求“带假设继续”时才制作受限草稿，并把假设单独记录。

开始分析前阅读 [来源与样本计划](references/source-plan.md)。编码前阅读 [消费者原话编码](references/evidence-coding.md)。这两份 reference 属于本 Skill，不是额外依赖。

## 工作步骤

1. 建立来源清单：文件、平台、时间、样本数量、采集方式和已知偏差。
2. 为每条材料分配匿名 `record_id`，保留必要的短摘录与来源，不收集任务不需要的身份信息。
3. 严格分开原话、编码和判断。先标记场景、问题、期望结果、顾虑、触发与替代方案。
4. 合并高度相似记录时保留原记录 ID、来源差异和反例。
5. 只描述当前样本中观察到的模式，不把出现次数写成人群比例。
6. 输出洞察卡；每张卡写清原话证据、暂定解释、反例、限制和待负责人确认的问题。

## 交付文件

在用户指定目录，或默认在 `open-marketing-output/consumer-language-insight/` 创建：

- `consumer-quotes.csv`：记录 ID、来源、日期、短摘录、场景、问题、期望、顾虑、标签。
- `insight-cards.md`：一张卡一个判断，链接到记录 ID。
- `evidence-gaps.md`：样本偏差、缺失字段、反例和下一轮补数建议。

不要大段复制受版权保护的内容。报告里的逐字摘录应短、必要、可追溯。

## 人工决定

最后请营销负责人确认：哪些表达可进入定位或创意；哪些只能当线索；是否需要补平台、购买评论或一手访谈。

不得替用户判断市场规模、购买因果、总体比例、真实销量或尚未提供的身份与商业关系。不得自动发布、投放、私信或修改平台账户。
